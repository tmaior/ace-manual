# Build, deploy and CI/CD

## Build

### Prerequisites

- Node.js 16+ (Dockerfile uses Node 20)
- Yarn (package manager)
- Docker (for image build)
- AWS CLI and kubectl/Helm (for deploy; Dockerfile installs them)

### Local build and run

```bash
# Install dependencies
yarn

# Development (with nodemon)
yarn start:dev

# Production
yarn start
# or
yarn start:prod
```

### Docker image (ace-infra)

- **Dockerfile**: `ace-infra/ace-commands-api/ace.commands-api.Dockerfile`
- **Base**: `node:20`
- **Installs**: AWS CLI v2, kubectl, Helm, git, gh, jq, zip, python3, safety, pyflakes, terraform 1.5.0, and other CLI tools used by executed scripts.
- **App**: `WORKDIR /app`; copy `package.json` → `yarn install` → copy app → run `devops_setup.sh` (from infra-repo); entrypoint: `get_secrets.sh` then `entrypoint.sh`.
- **Port**: 3000 (EXPOSE 3000); deployment may map container port 80 to host.
- **Secrets**: At runtime, `get_secrets.sh` fetches from AWS Secrets Manager and exports env vars; `entrypoint.sh` runs `yarn` and `yarn start:dev` (or start as configured).

Build (from repo root, with infra checked out):

```bash
# Example: build using infra Dockerfile
docker build -f infra-repo/ace-commands-api/ace.commands-api.Dockerfile -t ace/commands-api:local .
```

## Deploy (Kubernetes)

- **Manifests**: In **ace-infra** under `ace-commands-api/`: deployment, service, ingress, PVC/PV (for `/tmp/commands-workspace`), secrets (generated by CI from AWS Secrets Manager).
- **Namespace**: `apis` (from deployment YAML; CI may override per env).
- **Image**: ECR, e.g. `975635808270.dkr.ecr.us-east-1.amazonaws.com/ace/commands-api:<tag>`.
- **Probes**: Liveness `GET /health` on port 80; readiness `GET /api/health` on port 80.
- **Resources**: requests cpu 0.5 / memory 0.5Gi; limits cpu 1 / memory 1Gi.
- **Volume**: PVC for `/tmp/commands-workspace` (persistent workspace for temp scripts and resource health log file when debug is on).

## CI/CD (GitHub Actions)

### Development

- **Workflow**: `.github/workflows/eks-deploy.dev.yaml`
- **Trigger**: Push to `development`, `ace-feat/*`, `hotfix/*`, `bugfix/*`
- **Steps**: Checkout app + infra repo; copy DevOps scripts; assume IAM role (ace-dev-eks-role); login to ECR; build Docker image with infra Dockerfile; tag `dev-<timestamp>`; push to ECR; fetch secrets from `ace/dev/commands-api-secrets`; generate K8s Secret YAML; update deployment image and namespace (dev), EFS ID, ingress host (dev-*); apply manifests to cluster **development-ace-eks**, namespace **dev**.
- **Secrets**: INFRA_REPO_TOKEN, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY (for assume-role and ECR).

### Production

- **Workflow**: `.github/workflows/eks-deploy.prod.yaml`
- **Trigger**: Push to `main`
- **Steps**: Same pattern; IAM role **ace-prod-eks-role**; secrets from `ace/prod/commands-api-secrets`; cluster **production-ace-eks**; namespace **prod**; EFS ID for prod; no ingress host rewrite (prod hostnames).
- **Image tag**: `prod-<timestamp>`.

### Notes

- Dockerfile is in **ace-infra**; workflow checks out infra and uses `infra-repo/ace-commands-api/ace.commands-api.Dockerfile`.
- Namespace and EFS ID are env-specific (dev vs prod).
- Manual deploy: use the same flow (build image, push to ECR, update manifests, kubectl apply) or use a manual workflow if defined.
